# Enunciado oficial da 2ª Entrega (copiado do Canvas em 10/09/2026)

Fonte: Canvas, disciplina Programação Web (curso 94967), tarefa 278075.

Nesta segunda entrega, o grupo deverá apresentar a evolução do projeto de aplicativo a partir da ideia inicial já validada na 1ª entrega.

O objetivo desta etapa é demonstrar que a proposta está avançando de forma organizada, com definição visual da solução, planejamento das atividades por meio de metodologias ágeis e evidências iniciais do desenvolvimento do sistema.

Nesta fase, o grupo deverá contemplar três pilares principais:

  - Protótipo da solução

  - Planejamento e organização do projeto com Scrum e Kanban

  - Início da implementação

Importante:
No dia da entrega, os grupos deverão explicar o conteúdo do documento ao professor, apresentando de forma objetiva o protótipo, o planejamento do projeto e o estágio inicial da implementação.

Estrutura obrigatória do trabalho

  - Identificação do Grupo

O documento deve conter obrigatoriamente:

  - Nome do Grupo

  - Nome completo dos membros

  - RA de todos os integrantes

  - Protótipo da Solução

Nesta seção, o grupo deverá apresentar o protótipo inicial do aplicativo, demonstrando visualmente a proposta da solução e a estrutura básica da interface.

O protótipo deve conter:

  - Tela inicial

  - Telas principais do sistema

  - Fluxo básico de navegação

  - Identidade visual inicial do aplicativo

  - Organização coerente das funcionalidades apresentadas na 1ª entrega

O grupo deverá explicar:

  - Como o protótipo representa a proposta do aplicativo

  - Quais funcionalidades principais já estão refletidas nas telas

  - Como o usuário irá interagir com a solução

  - Se o protótipo foi desenvolvido com foco em Web

Importante:
O protótipo precisa estar finalizado e deve apresentar de forma clara a estrutura inicial da aplicação e a experiência esperada do usuário.

  - Planejamento do Projeto com Metodologias Ágeis

Nesta etapa, o grupo deverá demonstrar como o projeto será organizado utilizando conceitos de Scrum e Kanban.

O trabalho deve apresentar:

Scrum

  - Definição inicial do Product Backlog

  - Lista de funcionalidades, requisitos ou entregas previstas

  - Organização inicial das prioridades

  - Planejamento das próximas etapas do desenvolvimento

Kanban

  - Estrutura visual do fluxo de trabalho, contendo pelo menos:

  - A Fazer

  - Em Andamento

  - Concluído

O grupo deverá explicar:

  - Como as tarefas foram organizadas

  - Como ocorreu a divisão inicial das atividades entre os integrantes

  - Como Scrum e Kanban ajudarão no acompanhamento do projeto

  - Como essa organização contribui para a viabilidade do MVP dentro do semestre

  - Início da Implementação

Nesta seção, o grupo deverá apresentar evidências de que o projeto já iniciou sua construção técnica.

Pode incluir:

  - Estrutura inicial do projeto

  - Criação das primeiras telas

  - Configuração do ambiente de desenvolvimento

  - Primeiros trechos de código

  - Banco de dados inicial, se aplicável

  - Definição inicial de front-end e back-end

O grupo deverá informar:

  - Qual tecnologia está sendo utilizada

  - Se o projeto terá banco de dados

  - Se haverá back-end

  - O que já foi implementado até o momento

  - Quais partes ainda serão desenvolvidas nas próximas etapas

Importante:
Não é necessário que o sistema esteja funcional por completo nesta fase, mas deve haver evidências concretas do início do desenvolvimento.

  - Coerência com a 1ª Entrega

O grupo deverá manter alinhamento com a proposta apresentada anteriormente, garantindo coerência entre:

  - Problema real definido

  - Público-alvo

  - Setor da sociedade

  - ODS escolhida

  - Solução proposta

  - Protótipo desenvolvido

  - Planejamento apresentado

  - Início da implementação

  - Valor Gerado pelo Projeto

Retomar de forma objetiva o valor que a solução pretende entregar, considerando aspectos como:

  - Inclusão social

  - Educação

  - Sustentabilidade

  - Geração de renda

  - Melhoria de serviços

  - Impacto social, econômico ou ambiental

Checklist obrigatório (antes do envio)

  - Protótipo apresentado com telas principais

  - Fluxo inicial de navegação demonstrado

  - Product Backlog inicial definido

  - Quadro Kanban apresentado

  - Planejamento do projeto descrito

  - Evidências do início da implementação

  - Tecnologias do projeto informadas

  - Coerência com a proposta da 1ª entrega

  - Nome do Grupo

  - Nome dos Membros

  - RA dos Membros

Formato da entrega

  - Documento em PDF

  - Trabalho em grupo

  - Um membro do grupo realiza a entrega

  - Envio via Canvas

  - Apresentação oral do documento ao professor no dia da entrega

O grupo deverá utilizar obrigatoriamente o modelo disponibilizado para esta entrega, caso haja modelo específico.

Modelo Documento - 2a Entrega.docx

O trabalho deve demonstrar que o projeto avançou de forma visual, organizada e tecnicamente iniciada, respeitando a proposta de MVP viável para o semestre.

Trabalhos incompletos, sem protótipo, sem planejamento, sem evidências de implementação ou sem capacidade de explicação do documento no dia da entrega, poderão ter desconto na avaliação.
